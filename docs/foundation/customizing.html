Customizing

What you can override, and how. See Colors & Tokens for a visual swatch preview of the palette.

Two ways to customize

Basix exposes two independent customization surfaces:

MechanismWhen it appliesUse for
CSS custom propertiesRuntime, in the browser — no build step, no access to the source neededColours, radii, per-component sizing — anything you'd want to change on a live site or per-instance
SCSS variablesCompile time, via @use … with (…) before running sassBreakpoints, animation timing, the base spacing/radius scale — values every custom property is itself computed from

Token layers

Two layers of custom properties, not three — Basix does not use a separate primitive/raw-palette layer, since it targets a single brand rather than many themes sharing one palette.

LayerScopeExample
Semantic tokens:root, defined once in properties.scss--accent-color, --divider, --error
Component tokensThe component's own class — not :root, see Scope matters below--cal-accent, --chart-color-1, --menu-width

Component tokens usually default to a semantic token, so re-theming --accent-color already re-themes most components — the component tokens exist for the cases where you want a component to diverge from the global palette without touching anything else:

/* css/calendar.scss */
.cal {
  --cal-accent: var(--accent-color);
}

Spacing & radius

Not colour tokens — same value in light and dark. Compiled from the SCSS variables of the same name (see SCSS variables), so they always match what the components themselves use.

TokenValue

--radius-md0.6rem
--radius-lg0.8rem
--radius-panel1rem

--radius-full9999px

These custom properties make the values available to your CSS and reflect what Basix uses — they don't make the components themselves re-read the property at runtime. The components still compile their radius from the SCSS variables at build time. Change --radius-md from :root and your own elements pick it up instantly; changing what Basix's own buttons/cards use requires the SCSS route below.

Overriding semantic tokens

Load your stylesheet after css/style.css — both declare on :root at equal specificity, so source order decides:

The dark-mode trap

Basix ships its palette in three blocks: :root, [data-theme="dark"] (set by the theme toggle), and @media (prefers-color-scheme: dark) (the fallback before the toggle runs, or for pages that never wire it up). An override placed only on :root gets replaced again by whichever dark block applies — the accent color reverts to the default the moment dark mode activates. Cover all three. --accent-color-lighten and --accent-color-tint follow --accent-color automatically, but they resolve on :root: set --accent-color on :root / [data-theme="dark"], not on a child element, or they will keep the default accent.

Scope matters

Component tokens are declared on the component's own class, not :root. A directly-matched class selector always beats an inherited :root value, regardless of how the property is spelled — this is the single most common reason a token override silently does nothing:

Two more scoping pitfalls:

  • Flyout Menu's tokens are declared on two selectors together. Overriding only .flyout-menu leaves .flyout-overlay on the old --transition-speed, so the panel and its backdrop animate out of sync:
  • The Calendar's --cal-time-col-width and Flyout Menu's --menu-width are re-declared inside a mobile media query, at the same specificity but later in the source. An override that only targets the base selector gets silently reset below 768px / 480px.

All of the above carry !default, so they can be configured from a consuming stylesheet without forking the file:

// your-entry.scss
@use "@dodlhuat/basix/css/style" with (
  $spacing: 1.25rem,
  $border-radius: 0.5rem,
  $bp-md: 800px
);

Runtime properties — don't override

Set by component JavaScript to position and animate individual elements. They aren't theming knobs — overriding them fights the component's own layout logic instead of customizing it:

--path-length, --animation-delay, --delay, --span-col, --span-len, --span-lane, --span-lanes, --allday-lanes, --cont-before, --cont-after, --range-start, --range-end, --range-fill, --left, --right, --hex, --parent, --popover-arrow-offset
